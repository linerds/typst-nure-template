# Роботи ХНУРЕ в Typst (пакунок `nure`)

Пакунок сам оформлює титулки, поля, шрифт, інтервали, заголовки, нумерацію рисунків, таблиць, формул і лістингів, перенос таблиць, примітки, виноски, перелік джерел і додатки за ДСТУ 3008:2015. Твоя робота -- дані роботи, структура, текст і правильна розмітка. Нічого з того, що робить шаблон, не пиши руками.

Довідка в `references/` (читай потрібний файл, коли задача його стосується):

| Файл | Коли читати |
| --- | --- |
| [references/markup.md](references/markup.md) | Рисунки, таблиці, формули, код, списки, примітки, виноски, посилання, джерела, додатки |
| [references/data.md](references/data.md) | Поля `doc.toml` і `work(...)`, автори, викладачі, власні дисципліни (`data.yaml`) |
| [references/coursework.md](references/coursework.md) | Курсова робота (`cw`) і комплексний курсовий проєкт (`cw-v2`) |
| [references/api.md](references/api.md) | Усі експортовані функції, перевизначення стилю, макети титулки, власні сторінки, перехід з 0.2 |

## 1. Спершу визнач середовище

Не вгадуй версію й імпорт -- візьми їх з проєкту.

| Ознака в теці роботи | Імпорт | Збірка |
| --- | --- | --- |
| `.mise/config.toml` з `nure = { version = "X.Y.Z", … }` | `#import "@vendor/nure:X.Y.Z": *` | `mise run compile` → `main.pdf` |
| Пакунок у `~/.local/share/typst/packages/local/nure/X.Y.Z` (або створено `typst init @local/nure:X.Y.Z`) | `#import "@local/nure:X.Y.Z": *` | `typst compile main.typ` |
| Код пакунка скопійовано в проєкт (`lib/lib.typ`) | `#import "/lib/lib.typ": *` | `typst compile main.typ` |

- Якщо в проєкті вже є `main.typ`, версія в імпорті там головна; не змінюй її без прохання. Версія в імпорті й у `.mise/config.toml` мусять збігатися.
- Потрібен Typst 0.15+ (тип `path`). У mise-проєкті Typst викликай через `mise exec -- typst …`, щоб бачити `TYPST_PACKAGE_PATH`.
- Нова робота з mise: скопіювати `template/mise` з репозиторію (`git clone --depth 1 -b vX.Y.Z https://github.com/linerds/typst-nure-template.git`), потім `mise trust && mise install`.
- У mise-проєкті корінь Typst -- тека `src/`: рисунки, `bibl.yml`, `data.yaml`, код для лістингів кладуть усередину `src/` (типово `src/figures/`, `src/assets/`, `src/chapters/`). Файли поза `src/` прочитати не вийде.

## 2. Лабораторна, практична, КР, ІДЗ

`src/doc.toml` -- спільне для всіх робіт з дисципліни. Поля роботи стоять **до** першого `[[authors]]`/`[[mentors]]`, інакше TOML тихо віднесе їх до останнього блоку:

```toml
subject = "СМП"            # скорочення; повна назва підставиться з вбудованих даних

[[authors]]
name = "Косач Л. П."       # «Прізвище І. Б.»
edu-program = "КУІБ"
group = "24-1"             # разом з edu-program дає «КУІБ-24-1»
gender = "f"               # m/f: «Виконав»/«Виконала»
variant = 8                # необов'язково

[[mentors]]
name = "Шевченко Т. Г."
degree = "Доцент кафедри ПІ"
gender = "m"
```

`src/main.typ` -- тип, номер, тема й текст:

```typst
#import "@vendor/nure:0.3.0": *
#import style: spacing

#let w = work(
  ..toml("doc.toml"),
  type: "ЛБ", // ЛБ, ПЗ, КР, ІДЗ або будь-який текст
  number: 2,
  title: "Потік керування та алгоритмічні структури Bash",
)

#set document(..w.document)
#show: style.dstu.with(skip: 1)   // до титулки: титулка без номера, далі «2»

#report.title-page(w)             // layout: "complex" або "nure-iki" за вимогою кафедри
#title-heading(w)                 // «2 ПОТІК КЕРУВАННЯ …», підрозділи стають 2.1, 2.2

#v(-spacing)
== Мета роботи
Ознайомитися з умовними операторами й циклами Bash.

== Хід роботи
#v(-spacing)
=== Підготовка
...

== Висновки
У ході роботи ...

#bib(path("bibl.yml"))            // лише якщо є посилання на джерела

#show: style.appendices
= Код програми
#raw(read("assets/main.sh"), lang: "bash", block: true)
```

- Типова структура звіту: «Мета роботи», «Хід роботи», «Висновки», за потреби «Контрольні запитання». Якщо методичка задає іншу -- дотримуйся методички.
- Тему з форматуванням передавай вмістом: `title: [Тема з _курсивом_]`. Без теми: `title: none`.
- Велику роботу розбивай: `#include "chapters/task1.typ"`; у кожному такому файлі повторюй `#import "@vendor/nure:0.3.0": *` (і `#import style: spacing`, якщо потрібен).
- Збирай роботу з блоків, як вище, а не рецептом `pz-lb`: блоки дозволяють вільно змінювати порядок сторінок, додавати власні й працюють із `mise run rename` (йому потрібен `#let w = work(...)` у `main.typ`).

Курсова (`cw`) і комплексний курсовий проєкт (`cw-v2`) -- у [references/coursework.md](references/coursework.md).

## 3. Розмітка коротко

Подробиці й усі параметри -- [references/markup.md](references/markup.md).

```typst
= Аналіз предметної області <sec:analysis>   // з нової сторінки, великими, «1 …»
== Огляд аналогів <sub:analogues>            // 1.1
#utils.nheading[Вступ]                       // без номера, але у змісті

#fig(path("figures/scheme.png"), [Схема роботи], none, label: <fig:scheme>, width: 80%)
// третій аргумент: не вказано -- без примітки; none -- «(рисунок виконано самостійно)»; "cisco.com" -- «(за даними cisco.com)»

#tab(
  caption: [Результати вимірювань],
  columns: (1fr, 2fr, 2fr),
  header: ([№], [Напруга, В], [Струм, мА]),
  label: <tab:measurements>,
  [1], [3,3], [12],   // у тексті й таблицях десяткова кома; крапка -- лише у формулах
)

$ E = m c^2 $ <eq:einstein>
#utils.noindent де $E$ -- енергія; $m$ -- маса; $c$ -- швидкість світла.

#figure(
  ```bash
  for f in *.txt; do wc -l "$f"; done
  ```,
  caption: [Підрахунок рядків у файлах],
) <lst:count>

На @fig:scheme[рисунку] ..., у @tab:measurements[таблиці] ..., за @eq:einstein[формулою] ..., у @lst:count[лістингу] ... @mysql.   // джерело: [1]

#note[Текст примітки без слова «Примітка».]
Текст#footnote[Пояснення.] далі.

+ перший пункт;       // а)
  + вкладений;        // 1)
- маркер.             // –
```

## 4. Правила, які шаблон не виконає за тебе

1. **`path()` для файлів, що йдуть у пакунок**: `fig(path("figures/a.png"), …)`, `bib(path("bibl.yml"))`, `bib-path: path("bibl.yml")`. Звичайний рядок шукатиметься в теці пакунка. Власні виклики (`image("…")`, `read("…")`, `csv("…")`) -- звичайним рядком.
2. **`#v(-spacing)` між суміжними заголовками** без тексту між ними, зокрема `#title-heading(w)` → `==` і `==` → `===`. Потрібен `#import style: spacing`.
3. **Без крапки в кінці** заголовків, назв рисунків і таблиць.
4. **Переліки**: пункти з малої літери через `;`, останній -- з `.`.
5. **Формули**: номер отримує лише формула з міткою `<eq:…>`, на яку є `@eq:…` у тексті. Десяткові дроби пиши з крапкою (`$9.8$` → «9,8»), аргументи з дробами розділяй `;` (`$f(1.5; 2.5)$`). Пояснення познак: `#utils.noindent де …` без двокрапки.
6. **Посилання з відмінком** -- через підпис у дужках: `на @fig:x[рисунку]`, `у @tab:x[таблиці]`. Не пиши «у таблиці @tab:x» -- вийде «у таблиці Таблиця 1.1».
7. **Посилання на джерело** -- просто `@ключ`, без квадратних дужок: `[@mysql]` дасть «[[1]]».
8. **Мітки з префіксом типу**: `sec:`, `sub:`, `pt:`, `fig:`, `tab:`, `eq:`, `lst:`, `app:` -- не конфліктують між собою й з ключами `bibl.yml`.
9. **Примітка до рисунка чи таблиці** -- параметром `note:` у `fig`/`tab`, а не окремим `#note` після них.
10. **Шапку таблиці** задавай через `header:` у `tab` або `table.header(...)` у `figure(table(...))` -- інакше вона не повториться при переносі. Довгі таблиці не розбивай вручну й не став `placement: top`.
11. **Не більше 4 виносок** на сторінці.
12. **Порядок наприкінці**: основні розділи → `#utils.nheading[Висновки]` (у курсових) → `#bib(...)` → `#show: style.appendices` і додатки.
13. **Десяткова кома в тексті й таблицях** (`[3,3]`) -- шаблон її не ставить; крапку на кому він замінює лише у формулах.
14. **`bibl.yml`** (Hayagriva): лише типи `Book` і `Web`, інші не перевірені на відповідність ДСТУ. До переліку потрапляють лише процитовані джерела (`full: true` -- усі).
15. **Не редагуй файли пакунка.** Нова дисципліна, програма, університет -- `data.yaml` поруч із `main.typ` і `work(..., data: yaml("data.yaml"))`. Відхилення від ДСТУ за вимогою кафедри -- `style.overrides.*` або власні `set`/`show` після `style.dstu`.

## 5. Що пише шаблон -- не дублюй

Не набирай вручну: «Рисунок 1.1 –», «Таблиця 1.1 –», «Лістинг 1.1 –», номери формул «(1.1)», «Продовження таблиці», «Примітка.», «ДОДАТОК А», «ЗМІСТ», «РЕФЕРАТ», номери сторінок, номери розділів у тексті заголовків, великі літери в заголовках першого рівня, «Виконав/Виконала», повну назву дисципліни чи кафедри (беруться за скороченням). Нумерація скидається з кожним розділом сама; для наскрізної -- `style.dstu.with(section-numbering: false)`.

Рядковий код `` `ls -la` `` за ДСТУ виводиться звичайним шрифтом у лапках «ls -la». Моноширинний -- лише якщо кафедра дозволяє: `#show: style.overrides.inline-code` після `style.dstu`.

## 6. Перевірка

Після змін завжди збирай документ і виправляй усі помилки компіляції.

```sh
mise run compile                 # або: typst compile main.typ
mise run lint                    # dsty check --full src/main.typ, якщо є в проєкті
mise exec -- typst compile --ppi 60 src/main.typ "/tmp/nure-preview/p{0p}.png"   # сторінки як PNG
```

- Переглянь PNG сторінок, на яких щось змінював: титулку, переноси таблиць, підписи, нумерацію, додатки.
- Попередження про відсутній Times New Roman / Courier New -- не помилка: шаблон бере Liberation Serif / Mono. Не намагайся його «виправити» в коді.
- Помилка `fig` про рядок замість `path` -- обгорни шлях у `path()`. Повідомлення `work` про відсутнє поле -- додай поле, яке воно називає.
- Здача: `mise run rename` копіює PDF як `ЛБ2_Косач_КУІБ-24-1_СМП.pdf`.

Чекліст перед здачею:

- [ ] У `doc.toml` поля роботи стоять до `[[authors]]`/`[[mentors]]`, дати без лапок.
- [ ] `#set document(..w.document)` і `#show: style.dstu.with(skip: 1)` -- до титулки.
- [ ] `#v(-spacing)` між усіма суміжними заголовками.
- [ ] Немає крапок у кінці заголовків і підписів; переліки з `;` і `.` в останньому пункті.
- [ ] Усі файли в `fig`/`bib` обгорнуті в `path()`.
- [ ] Формули з номером мають мітку й посилання; під формулами `#utils.noindent де …`.
- [ ] Кожен рисунок, таблиця й лістинг згадані в тексті через `@…`.
- [ ] Не більше 4 виносок на сторінці.
- [ ] `bib` стоїть перед `#show: style.appendices`.
- [ ] Документ компілюється без помилок, сторінки переглянуто.
